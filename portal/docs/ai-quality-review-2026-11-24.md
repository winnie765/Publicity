## Weaknesses corrected

1. Correct JSON did not mean a writing draft preserved supplied facts. A draft could invent an event date, count, venue, URL or testimonial and pass the old Studio validator.
2. Some generic reports accepted platform claims unrelated to the cited fact, written-out quantities or repeated recommendations.
3. Generic report cache hits were returned without re-running current report validation. Cached writing was only structurally checked.
4. The older evidence builder could emit a format ratio/lift across incompatible interaction definitions. It now calls the existing `compatibleInteractions` policy before emitting that comparison. Ineligible groups produce a precise withheld-comparison fact. Raw counts/averages and all underlying analytics formulas remain unchanged.
5. Privacy controls varied by entry point; planner context included unnecessary post/campaign titles and post identifiers.
6. Studio said “Nothing is sent or published,” although generation sends the supplied brief to Gemini. Its notice now correctly distinguishes external AI submission from publishing.
7. CMS writing cleared a prior draft before requesting a replacement; a failed request now retains it.
8. The old thinking configuration applied a zero budget to every `gemini-2.5-*` model, including models that may not support disabling thinking. The shared policy limits explicit budget handling to compatible Flash-family names; other models use their provider settings.

## Implemented checks and limits

`lib/ai-safety.ts` is a deterministic, conservative screen, not an independent semantic fact checker:

- Blocks recognised Singapore identity numbers, credential/token patterns, identifiable names combined with private contacts, and labelled participant/clinical information before external submission. Inputs are not silently rewritten; staff remove/rephrase sensitive data themselves. Checks also run before cache reuse in supported generation paths.
- Writing checks cover supported English/Chinese date forms, clock times, numeric anchors, explicit participant counts, some written quantities, quotations, original links, labelled organisation/programme/location values, selected named-venue patterns and unsupported achievement/medical phrases. Confirmed source data stays unchanged. A rejected result is withheld, with a useful message.
- Chinese numeral dates/counts and supplied bilingual dates have specific regression coverage. This is not exhaustive multilingual named-entity or medical-claim verification.
- Names/quotes cannot always be automatically translated safely. Preserve official names and supply approved bilingual facts/quotes in the source. Previous generated prose is not treated as verified evidence for Studio refinements; keep confirmed facts in the brief.
- Analysis checks preserve canonical evidence/statistics, reject unsupported written quantities and mismatched measured-platform claims, and withhold high/low classifications when the cited post comparison says Insufficient Evidence. Exact normalised duplicates in the main insight array are rejected. This does not establish that every qualitative inference is correct or remove all semantic overlap across pages.
- Existing Source → calculated observation → interpretation/hypothesis → proposed action distinctions remain. Generic confidence displays now explicitly say they are AI assessments, not statistical confidence or independent factual verification.
- New shared transport validates the fixed Gemini endpoint, caps context at 120,000 characters, handles provider errors/rate limits/timeouts with safe messages, requires a completed response and parseable structured JSON, and excludes reasoning parts from displayed content through existing parsers. It adds no automatic retries or extra model calls.
- Current policy/model/reasoning settings participate in cache keys. Generic reports and writing are revalidated on cache reads. Existing expiry windows, daily budgets and request leases remain in place. A policy change can cause a one-time increase in cache misses, bounded by the existing daily limit.

Pattern screening can miss unlabelled personal information, subtle changed names/venues, altered relationships between otherwise supplied numbers, unsupported qualitative claims, or paraphrased medical claims. It can also reject legitimate reformattings or translations. Passing is **not** an “all facts verified” badge. Staff must check original records, official event details, sources, consent and suitability before using any output.

## Prompt and model settings

- Default `GEMINI_MODEL` remains `gemini-2.5-flash`; no automatic upgrade or paid provider was introduced.
- Existing temperatures remain: analysis 0.2, chart design 0.1, caption writing 0.4, Studio 0.5.
- Output-token caps remain 4,096 / 8,192 according to the existing task. Existing per-task request timeouts remain 30–55 seconds.
- Shared analytical instructions require the observation, decision implication, uncertainty, practical experiment/measurement and evaluation metric, without unsupported causes, demographics, “optimal” schedules or cross-platform metric substitutions.
- Shared writing instructions require confirmed facts, natural Chinese, exact proper names, respectful senior communication, distinct platform purpose, placeholders for missing details and reviewable prose. The Studio base prompt was shortened to avoid simply stacking longer instructions.
- `AI_ANALYSIS_THINKING_BUDGET` is optional and server-controlled. Default is **0**. For recognised Gemini 2.5 Flash-family configurations, analysis/chart requests accept 0 or an integer 512–2048; invalid settings fall back to 0. Writing stays at 0. Reasoning traces are not requested/displayed. Other configured models receive no forced `thinkingConfig` from this policy. Check provider compatibility before enabling it; an alias/provider change can alter supported settings.
- Optional extra reasoning is **not enabled** by this change. A local configuration test confirms request construction; no live evaluation proves a quality/latency benefit. Use the lowest approved setting that passes a staged human evaluation. Google documentation: [thinking configuration](https://ai.google.dev/gemini-api/docs/thinking), [structured output](https://ai.google.dev/gemini-api/docs/structured-output). A schema is not a substitute for source verification.

## Repeatable evaluation

Run from `portal`: `npm run test:ai-quality` (or the repository Node executable with `scripts/test-ai-quality.mjs`). It compiles both the original feature sources and current sources in isolated directories, compares the **same inputs and synthetic responses**, and never calls Gemini. Baseline revision: `e8557120121cbd90be2121a6ffaba12d713566f8`; optionally set `AI_EVAL_BASELINE_REVISION` to review another Git revision.

The 30-case matrix covers confirmed bilingual facts, missing-details placeholders, creative numbered ideas, recorded zero, source venues, invented dates/times/counts/quotes/links/medical claims, markup, swapped date components, privacy-sensitive input, executive interpretation, evidence references, unsupported numerical/spelled-out growth, wrong-platform evidence, duplicate actions, insufficient comparisons and approved/unsupported/injected/conflated dashboard fields.

Additional regressions cover Chinese numeral dates/counts, clinical claims, request failures, malformed/incomplete JSON, rate limits, oversized context before sending, stale cached narrative, reasoning settings, and compatible versus incompatible format evidence.

| Automated acceptance-policy score | Original | Improved |
| --- | ---: | ---: |
| Correct accept/reject decision on the final curated 30 fixtures | 13/30 | 30/30 |

These are validation-policy scores, **not live-model accuracy rates**, and the fixture distribution is intentionally adversarial. No quality claim should be inferred for unseen prompts.

Examples, explicitly synthetic rather than live AI generations:

| Source | Fixture response | Original result | Improved result |
| --- | --- | --- | --- |
| Event details only; no attendance | “We welcomed 200 participants.” | Structurally accepted | Withheld for unsupported quantity/count |

Results and the exact fixtures are written to `.sites-runtime/ai-quality/results.json` and `cases.json`; these contain only synthetic data. They are not a new application data store. The original source comparison requires Git history; it does not reset or edit the working tree.

### Human quality rubric

Score each of factual accuracy, analytical depth, relevance, specificity, actionability, clarity, consistency and privacy from 0–4:

- 0: unsafe, incorrect, irrelevant or unusable.
- 1: major omissions/errors; substantial rewrite needed.
- 2: usable only after material corrections; shallow or generic reasoning.
- 3: accurate within supplied evidence, specific and practical; minor edits.
- 4: accurate, decision-relevant, concise and actionable, with explicit limits and suitable language.

For analysis, a score above 2 requires a source-supported observation, a distinct practical implication and a measurable proposed next step. For creative writing, judge platform fit, natural Chinese/English, respectful wording and faithful facts rather than requiring analytical structure. A fabricated critical fact, disclosed sensitive information or unsupported causal guarantee is an automatic failure regardless of average score.

Human scores are **not assigned** in this change. Recommended next evaluation: two reviewers independently score original/improved live outputs for the same approved, anonymised cases at the same model/settings, reconcile disagreements, and retain verified evidence alongside scores. Use the existing daily allowance, inspect provider token usage and latency, and approve any additional call budget first. Do not send production personal records merely to run the evaluation.

## Remaining limitations and deployment

- Real-model factual/qualitative quality, natural Chinese, latency, token consumption and live rate limits remain untested. No before/after live outputs were fabricated.
- Named-entity and medical/causal claim checking is partial; source anchoring cannot establish every semantic relationship. Staff approval remains essential.
- Generic analytical facts can still describe heterogeneous account/content mixes. A new gate protects explicit format lifts; underlying source/period/coverage limitations must still be read. Only the Analyst's prequalified source proof supports its stronger canonical findings.
- Detectors are not a comprehensive DLP system or a PDPA compliance guarantee. Review organisational rules and Gemini account/data terms; remove unnecessary personal information from configured labels and free text.
- No new database migration, API key or provider is needed for these AI changes. Existing Gemini setup remains authoritative. Optional reasoning configuration is an administrator decision after live evaluation.
- Password-only login has subsequently been restored. The existing WORKSPACE_PASSWORD and database connection are required; email-service configuration is not used. See `docs/password-login.md`.
- Deploy only after reviewing the listed test limitations and the current login setup. No deployment was performed.
